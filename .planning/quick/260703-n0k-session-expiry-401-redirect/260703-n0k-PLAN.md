<objective>
Gerer proprement l'expiration de session (JWT backend 401) dans Loadsheet-autonome sans perte de donnees.

Aujourd'hui, quand le JWT expire (SESSION_DURATION_MS = 8h) alors que l'agent est toujours "connecte" cote client, les appels API renvoient un 401 avec un message cryptique ("Non autorise", "Erreur: GET /api/recipients 401"). L'expiration n'est reverifiee qu'au chargement de page.

Ce plan implemente l'approche VERROUILLEE par l'utilisateur (a ne pas remettre en question) :
1. Intercepteur centralise des 401 pour tous les fetch vers /api/* (send-email, recipients, clients).
2. Sauvegarde auto du manifeste en cours (storage chiffre existant) AVANT redirection, zero perte.
3. Redirection vers le login avec message clair "Session expiree, reconnectez-vous.".
4. Avertissement non-bloquant ~10 min avant l'expiration (base sur data.expiry stocke par setSession).

Purpose: fiabiliser le flux operationnel terrain (core value : PDF envoye aux bons destinataires sans perte de donnees).
Output: intercepteur apiFetch + timer d'avertissement + auto-save silencieux + messages login clairs, couverts par tests.

## Contraintes projet (CLAUDE.md — NON negociables)
- JS vanilla uniquement, aucun framework.
- Toute donnee utilisateur en innerHTML passe par esc(). Les messages injectes ici utilisent textContent (anti-XSS natif) — pas d'innerHTML.
- Les fonctions storage (getSavedManifests, writeSavedManifests, collectData) sont async — await obligatoire AVANT logout().
- Retro-compatibilite : ne pas modifier le format de stockage, reutiliser writeSavedManifests/getSavedManifests tels quels.
- Bump APP_VERSION dans app.js (visible login + app + PDF) + package.json en miroir.
- Toute nouvelle fonctionnalite couverte par des tests dans tests/tests.html.

## Decision d'architecture (contrainte du harness de test)
Le harness `tests/run-harness.cjs` charge lists.js + clients.js + app.js mais **PAS auth.js** (il stub `window.getJwt` et `window.logout`). Pour rester testable sans casser les tests send-email existants :
- La logique testable (apiFetch, handleSessionExpired, saveManifestSilently, computeWarningDelay, scheduleExpiryWarning) vit dans **app.js** (charge par le harness).
- auth.js ne recoit que des ajouts minimes (accesseur d'expiry, messages login) references via `typeof ... === 'function'` guards.
- apiFetch appelle le `fetch` global dynamiquement -> les stubs `window.fetch` des tests existants continuent d'intercepter. Les stubs existants ne renvoient pas de `status` -> `res.status === 401` est false -> passthrough -> aucune regression.
</objective>
